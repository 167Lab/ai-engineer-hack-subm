# AI Data Engineer Assistant (Проект в разработке)

Этот проект предназначен для автоматизации базовых задач инженера данных с использованием мультиагентной системы (МАС) на базе LLM. Система анализирует источники данных, рекомендует целевые хранилища, генерирует DDL‑скрипты, создаёт ETL‑пайплайны (Apache Airflow) и формирует отчёт.

## Описание и статус

## Архитектура
Проект состоит из нескольких подсистем:

- Backend (Django + DRF): REST API, сервисы генерации DAG, анализаторы данных, интеграция с МАС.
- Frontend (React + TypeScript): мастер настройки источников и пайплайнов, предпросмотр DAG (в разработке, интеграция будет подключаться позже).
- Инфраструктура (Docker Compose): Apache Airflow (webserver, scheduler), PostgreSQL (метаданные Airflow), ClickHouse, Hadoop HDFS (single‑node).
- Мультиагентная система (МАС): находится в `backend/apps/agents/`, реализует последовательность агентов для анализа, генерации DDL, построения пайплайна и отчёта.

Структура репозитория (упрощённо):

- `backend/` — Django API, сервисы, анализаторы
- `frontend/` — клиентское приложение (React)
- `infra/airflow/` — окружение Airflow (DAGs, Dockerfile, requirements)
- `docker-compose.yml` — инфраструктурные сервисы
- `backend/apps/agents/` — МАС (ядро, агенты, инструменты, конфиги)

## Быстрый старт

### Вариант A: Docker Compose (рекомендуется для демонстрации)
1) Установите Docker и Docker Compose.
2) Запустите инфраструктуру:
   - Airflow web UI будет доступен на `http://localhost:8080`
   - Backend API — на `http://localhost:8000`
   - Frontend — на `http://localhost:3000`

3) Поместите примеры данных в директорию `sample_data/` (монтируется в контейнер Airflow).

Примечание: команды запуска намеренно не приведены, поскольку окружения могут отличаться. Используйте стандартные команды docker‑compose в соответствии с вашей ОС/средой.

### Вариант B: Локальный запуск компонентов (для разработки)
- Backend: Python 3.10+, установить зависимости из `backend/requirements.txt`, настроить `DJANGO_SETTINGS_MODULE=config.settings`, запустить сервер разработки.
- Frontend: `npm install` и `npm run dev` в каталоге `frontend/`.
- Модели LLM: получить ключи API, выбрать модели (например, `llama3.2`, `qwen2.5:14b`).

## Конфигурация
Основные параметры находятся в `backend/apps/agents/config/general_config.yaml`:

- `llm_config` — выбор провайдера: `ollama`, `openai`, `groq`, `anthropic`, либо `hybrid`.
  - `ollama.enabled`, `url`, `models.*`, `temperature`, `max_tokens`.
  - `cloud.enabled`, `provider`, `api_key` (через переменные окружения), `models.*`.
  - `model_selection.strategy` и `fallback` — стратегия выбора и резервное переключение.
- `agents_config` — поведение агентов (включая `verbose`, таймауты, сохранение промежуточных результатов).
- `tools_config` — параметры работы инструментов (размер образца, лимиты файлов и пр.).
- `pipeline_config` — дефолтные настройки создаваемых DAG (расписание, ретраи и т. д.).

Промпты агентов находятся в `backend/apps/agents/config/prompts/` и могут настраиваться без изменения кода.

## API (Backend)
Базовый префикс: `/api/v1`

- `POST /analyze` — анализ источника данных c использованием МАС (вход: тип источника и параметры подключения/файла; выход: метаданные, профиль, рекомендации по хранилищу, при успешном выполнении — DDL, конфигурация пайплайна и отчёт).
- `POST /generate_dag` — генерация Python‑кода DAG на основе параметров пайплайна (без запуска МАС).
- `POST /deploy_dag` — деплой сгенерированного DAG в Airflow (если настроена интеграция).
- `GET /recommendations` — получение рекомендаций по источнику (через сервисную логику).

Форматы запросов/ответов см. в сериализаторах `backend/apps/api/serializers.py` и в исходниках views.

## Мультиагентная система (МАС)
Код МАС расположен в `backend/apps/agents/` и включает:

- `core/` — ядро (состояние, менеджер LLM, общий исполнитель, граф на LangGraph):
  - `state.py` — структура состояния МАС.
  - `llm_manager.py` — гибридный менеджер (Ollama + облака). Внимание: гибрид сейчас отключён из‑за конфликтов зависимостей.
  - `agent_executor.py` — базовая логика подготовки сообщений, логирования и обработки ответов.
  - `graph.py` — определение графа из узлов‑агентов (input → ddl → pipeline → report) и интерактивного режима.
- `agents/` — агенты:
  - `input_analyzer.py` — анализ метаданных и образца, выбор хранилища, генерация рекомендаций.
  - `ddl_generator.py` — генерация DDL с оптимизациями под PostgreSQL/ClickHouse/HDFS (Hive/Spark SQL).
  - `pipeline_generator.py` — генерация кода DAG Airflow (ETL: extract/transform/load, логирование, retries).
  - `report_generator.py` — формирование отчёта в Markdown (двухчастная структура: «общие сведения» и «технические детали»).
- `tools/` — инструменты, обёртки над существующими анализаторами (`backend/analyzers/*`).
- `config/` — конфигурация и промпты.
- `integration.py` — интеграция МАС с Django API.
- `test_mas.py` — локальное тестирование без фронтенда.

Поточность работы МАС:
1. Извлечение метаданных и образца → профилирование → черновые рекомендации (инструменты).
2. Анализ LLM → выбор хранилища и аргументация (input analyzer).
3. Генерация DDL для выбранного хранилища (ddl generator).
4. Генерация Airflow DAG (pipeline generator).
5. Формирование отчёта (report generator).
6. (Опционально) Интерактивный режим с обратной связью пользователя между этапами.

## Используемые технологии
- Язык: Python (Backend), TypeScript (Frontend)
- Backend: Django, DRF
- LLM и агенты: LangChain, LangGraph, Ollama (локальные модели)
- Оркестрация: Apache Airflow
- Хранилища: PostgreSQL, ClickHouse, HDFS
- Контейнеризация: Docker Compose

## Известные проблемы и ограничения
1) Гибридный LLM‑режим временно недоступен:
2) Деплой DAG в Airflow реализован базово; детали подключения и авторизации настраиваются в окружении и/или Docker Compose.
3) Поддержка Kafka/Spark‑streaming запланирована, но не входит в MVP.

## Дорожная карта
- Устранение конфликтов зависимостей и включение гибридного LLM‑режима.
- E2E‑тесты для сценария CSV → PostgreSQL/ClickHouse (анализ → DDL → DAG → загрузка).
- Улучшение генераторов для ClickHouse/Hive (партиционирование, TTL, bucketing, schema evolution).
- Интеграция с фронтендом (возможность правок между этапами, предпросмотр DAG/DDL, пошаговые подсказки).
- Поддержка Kafka и потоковых сценариев, инкрементальные загрузки, мониторинг качества данных.
